Mon organisation avec Claude : noter, trier, exécuter, clôturer

Donnez-lui une ligne comme vous voulez : chaque ligne devient un rendez-vous, un rappel, ou une session Claude Code qui travaille pendant que vous faites autre chose. Quand vous envoyez un message et le cochez, la note et la liste de tâches se mettent à jour toutes seules.

Reprendre tout le dispositif

L'installateur se colle dans le Terminal. Le prompt se colle dans Claude Code, qui lit l'installateur et demande votre accord avant de le lancer.

Schéma global

  1. Noter. Dictez, écrivez ou demandez à Claude. Ce sont des options, à vous de prendre la plus pratique : la dictée n'est jamais obligatoire.
  2. Trier. cc inbox envoie chaque ligne vers le Calendrier, les Rappels ou le cockpit.
  3. Exécuter. Les sessions Claude traitent le cockpit, consignent ce qu'elles ont fait et vous laissent des brouillons.
  4. Clôturer. Vous envoyez un brouillon et le cochez. En cinq minutes, sa ligne reçoit un ✅ et sa tâche quitte le cockpit.

Ce que vous obtenez

CommandeCe qu'elle fait
ccchoisit un projet et ouvre (ou rouvre) sa session Claude Code ; cc <nom> -c reprend la dernière conversation
cc inboxlit la note du jour dans Apple Notes, classe chaque ligne (tâche, rendez-vous, rappel, avec une priorité), montre le plan puis répartit : les rendez-vous au Calendrier, les rappels aux Rappels, les tâches dans leur propre session. --auto lance les tâches en arrière-plan, en autonomie
cc cockpit · cc runune page avec les tâches par priorité (à faire, en cours, à relire, à vous), ce qui vous attend, les sessions actives et le journal du jour ; cc run confie toutes les tâches ouvertes à une file qui lance jusqu'à trois sessions Claude à la fois, P1 d'abord, chacune dans son dossier de projet, résultats dans output/
cc todo "…"ajoute une ligne à la note du jour dans Apple Notes (créée dans le dossier Claude si elle n'existe pas) ; les sessions Claude Code peuvent le faire aussi si vous le leur demandez
cc me · cc clean · cc resetmarque une tâche comme vous revenant (envoyer, appeler, décider : jamais confiée à une session) ; ferme les sessions terminées ; remet une tâche à « à faire »
cc memo · --messagecompile le travail de la semaine (journal des sessions, notes de projet, git) en un brouillon de mémo, puis en un message court avec des demandes nominatives et des échéances
cc commsune banque de messages en brouillon, poussée dans une liste Rappels, modifiable et copiable depuis le téléphone. Cochez-en un une fois envoyé : done-sync.py le marque comme envoyé, coche sa ligne dans la note et ferme sa tâche, toutes les cinq minutes
Clic droit → ServicesAccentuer corrige les accents français d'un texte sélectionné (pour un clavier américain) ; Launch idea transforme une ligne de note sélectionnée en session

Chaque dossier de projet contient un CLAUDE.md (ce qu'est le projet, où sont les données brutes, les règles) : une session n'a jamais besoin qu'on lui réexplique le contexte. Les données brutes sont en lecture seule partout.

Si vous venez de VS Code

Vos conversations Claude Code dans VS Code sont gardées sur le disque, par dossier de projet : fermer les fenêtres ne fait perdre que ce qui tournait à cet instant. Pour en reprendre une depuis le terminal : cc <nom> -c reprend la dernière conversation de ce dossier, ou cd dans le dossier puis claude --resume pour choisir dans une liste. Le contexte du projet se trouve dans le CLAUDE.md de chaque dossier, que chaque nouvelle session lit toute seule. Utilisez zsh, le shell par défaut du Mac : cc n'existe pas dans bash.

Installer en trois étapes

1

Claude Code sur le Mac

Il vous faut un compte Claude (Pro ou Max), l'application Claude pour ordinateur et Claude Code. Le guide le plus clair pour les non-développeurs est Install Claude Code (Mac) de Chris Blattman, en anglais. En bref :

curl -fsSL https://claude.ai/install.sh | bash
claude        # connectez-vous une fois, puis tapez n'importe quoi pour vérifier qu'il répond

Homebrew est nécessaire pour tmux et fzf : brew.sh, une commande à coller.

2

Le kit, en un copier-coller

Le script ci-dessous contient tous les fichiers du kit (25 fichiers, tous en texte brut, rien n'est téléchargé ailleurs). Il les écrit dans ~/claude-kit et lance l'installateur : lanceur, scripts, actions rapides, configuration tmux, dossier scratch avec un modèle de projet, et une ligne dans votre .zshrc. Lisez-le d'abord si vous le souhaitez : c'est tout l'intérêt de le fournir en texte.

  ou le télécharger (.zsh, 117 Ko)

Puis dans le Terminal : collez, appuyez sur Entrée. Ou, pour le lancer directement depuis le presse-papiers :

pbpaste | zsh
3

Sécuriser, puis premier essai

python3 ~/.config/claude-launcher/merge-settings.py   # sandbox et règles de refus dans ~/.claude/settings.json
cc ls                 # doit afficher : scratch
cc new first-idea     # un projet avec son CLAUDE.md, Claude s'y ouvre

Le script de fusion sauvegarde vos réglages, garde toutes vos règles, refuse un fichier déjà cassé (et indique la ligne), puis valide le résultat. Ne collez pas l'extrait à la main : un { ... } oublié casse tout le fichier.

Dans Apple Notes, créez un dossier nommé Claude (le kit ne lit rien d'autre) et, dedans, une note intitulée to dos <date du jour> avec trois lignes : un rendez-vous (« appeler X jeudi 15h »), un rappel (« envoyer le fichier à Y demain »), un travail (« rédiger une synthèse d'une page sur … »). Puis cc inbox. macOS demandera une fois d'autoriser le Terminal à piloter Notes, Calendrier et Rappels.

Pour chaque dossier de travail existant : cd dedans, cc add, puis demandez à Claude, dans la session, d'écrire le CLAUDE.md du projet. Ensuite, cc <nom> l'ouvre avec son contexte.

La routine quotidienne

QuandQuoi
À tout momentAjoutez des lignes à la note du jour : dictez (Siri : « note : … »), écrivez, lancez cc todo "…", ou demandez à une session Claude. Des lignes, pas des paragraphes : un verbe, l'entrée, le résultat attendu.
Le matin, sur le Maccc inbox. Les rendez-vous et rappels se rangent, les tâches arrivent au cockpit reformulées en verbe + entrée + résultat. cc me <id> sur celles que vous seul pouvez faire, puis cc run, et vous pouvez partir.
De retour au bureaucc cockpit : les tâches à relire ont leurs résultats dans output/, avec un README qui dit quoi vérifier. cc <session> puis claude -c pour continuer avec la session qui l'a fait ; cc clean pour fermer le reste.
Dans la journéecc pour passer dans une session ; Option+←/→ pour naviguer entre elles ; Ctrl-b d pour tout laisser tourner.
Quand vous envoyezCopiez un brouillon depuis Rappels, envoyez-le vous-même, cochez-le. La note et le cockpit suivent en cinq minutes.
Chaque semainecc memo, dictez ce que les sessions ne peuvent pas savoir, cc memo --message, envoyez.

Sécurité

La règle : Claude rédige, vous envoyez. Dans cette installation, Claude n'a aucune connexion à votre messagerie, à WhatsApp ni à votre agenda. Il ne peut donc envoyer aucun message à votre place, et il ne circule pas librement dans tout votre ordinateur.

Garder la sandbox, ajouter de petites exceptions

Si la sandbox vous gêne, ne la désactivez pas : les sessions en file en dépendent, et sans elle rien ne les encadrerait. Exemptez plutôt les quelques commandes sans risque dont vous avez besoin, dans ~/.claude/settings.json :

"sandbox": {
  "enabled": true,
  "autoAllowBashIfSandboxed": true,
  "excludedCommands": [
    "pbcopy",
    "pbpaste",
    "open *",
    "python3 ~/.config/claude-launcher/notes_ideas.py *"
  ]
}

Cela rétablit le presse-papiers, l'ouverture de fichiers et la lecture de votre note de to-dos. N'exemptez pas osascript : il peut piloter Mail, ce qui annulerait la première ligne du tableau ci-dessus.

Ce que cela ne protège pas

  • Les connecteurs que vous ajoutez. Si vous connectez votre messagerie à Claude, cette page ne s'applique plus. Gardez le mail et WhatsApp à l'écart.
  • Vos propres autorisations. Vous pouvez accepter une commande hors sandbox quand on vous le demande. Lisez la question avant d'accepter.
  • La lecture. La sandbox limite l'écriture bien plus que la lecture : bloquez ce que vous ne voulez pas voir lu.
  • Les données sensibles. Ce qu'une session lit est envoyé à Claude pour être traité. Vérifiez vos propres règles avant de l'orienter vers des données personnelles ou de recherche.

Le détail des niveaux

NiveauRègle
NotesSeul le dossier Notes « Claude » est lu ; jamais les notes verrouillées ; une ligne commençant par 🔒, privé ou // est ignorée. La synchronisation des coches n'ouvre que les notes dont le titre contient « To dos ».
DisqueSandbox de Claude Code (Seatbelt, appliqué par macOS) : les sessions n'écrivent que dans leur dossier de projet et dans le journal, le cockpit et la file ; elles ne lisent jamais ~/.ssh, les trousseaux, les cookies, le mail, les messages, les fichiers .env ni les clés ; elles n'écrivent jamais dans un dossier raw/. Les dossiers cloud (~/Library/CloudStorage : Dropbox, iCloud Drive) peuvent refuser les commandes en sandbox avec « Operation not permitted » : testez les vôtres avant de mettre en file un travail qui en dépend.
RéseauLes commandes shell n'atteignent qu'une courte liste de domaines ; la recherche web passe par les outils de Claude, autorisés pour une liste de sources de référence que vous pouvez étendre.
SecretsClés d'API dans le trousseau macOS : security add-generic-password -a "$USER" -s <nom> -T /usr/bin/security -U -w (le -T évite une demande de mot de passe à chaque lecture).
AutonomieLes sessions en file tournent en acceptEdits : modifications de fichiers et commandes en sandbox autorisées, tout le reste refusé plutôt que demandé. Elles n'envoient, ne publient, ne poussent et ne suppriment jamais rien.

En cas de blocage

SymptômeSolution
launchctl list | grep cc-queue affiche 126un script a perdu son droit d'exécution : chmod +x ~/.config/claude-launcher/*.zsh, puis relancez zsh ~/claude-kit/install.sh
« settings.json: invalid JSON »en général un exemple collé tel quel : corrigez la ligne indiquée, puis lancez merge-settings.py
La file se vide sans rien produiretail ~/scratch/.queue/done/queue.log et les notes/run-*.log dans le dossier de la tâche
Une coche n'atteint pas la notepython3 ~/.config/claude-launcher/done-sync.py --dry-run liste ce qui serait synchronisé ; un message doit avoir son lien --task pour fermer une tâche
Un résultat reste vaguela ligne de tâche l'était : réécrivez-la en verbe + entrée + résultat, cc reset <id>, cc run
Vous ne savez plus où vous en êtescd ~/scratch && claude, puis demandez : « où en est la file ? »

Ce que ce n'est pas

Le kit n'envoie rien. Les messages et les mails sont des brouillons que vous copiez et envoyez vous-même ; les sessions écrivent des fichiers, elles ne publient jamais. Il ne touche pas aux données brutes. Il ne partage rien entre machines : l'état vit dans ~/scratch et ~/.config/claude-launcher sur votre Mac. Et c'est un ensemble de fichiers zsh et Python lisibles en un après-midi, ce qui explique qu'il soit partagé ainsi plutôt que sous forme d'application.
