Setup: capture, sort, execute, close

Give it a line however you like: every line becomes a calendar entry, a reminder or a Claude Code session that works while you do something else. When you send a message and tick it, the note and the task list update themselves.

Take the whole setup with you

The installer goes in Terminal. The prompt goes in Claude Code, which reads the installer and asks before running it.

Global schema

  1. Capture. Dictate, type, or ask Claude. These are alternatives, so use whichever is handy: dictation is never required.
  2. Sort. cc inbox sends each line to Calendar, Reminders or the cockpit.
  3. Execute. Claude sessions work through the cockpit, log what they did and leave drafts for you.
  4. Close. You send a draft and tick it. Within five minutes its note line gets a ✅ and its task leaves the cockpit.

What you get

CommandWhat it does
ccpick a project, open (or re-attach) its Claude Code session; cc <name> -c resumes the last conversation
cc inboxreads today's Apple Note, classifies each line (task / event / reminder, with a priority), shows the plan, then dispatches: events to Calendar, reminders to Reminders, tasks to their own session. --auto runs tasks detached and autonomously
cc cockpit · cc runone page with tasks by priority (to do / running / to review / yours), what's waiting on you, running sessions, today's log; cc run hands every open task to a background queue that starts up to three headless Claude sessions at a time, P1 first, each in its project folder, results in output/
cc todo "…"add a to-do line to today's note in Apple Notes (created in the Claude folder if missing); Claude Code sessions can do it too when you ask them
cc me · cc clean · cc resetmark a task as yours (send, call, decide: never given to a session); close finished sessions; put a task back to “to do”
cc memo · --messagecompiles the week's work (session ledger, project logs, git) into a memo draft, then into a short message with named asks and deadlines
cc commsa bank of drafted messages pushed into a Reminders list, editable and copyable from the phone. Tick one when it is sent: done-sync.py marks it sent, ticks its line in the note and closes its task, every five minutes
Right-click → ServicesAccentuer fixes French accents in any selected text (for a US keyboard); Launch idea turns a selected Note line into a session

Each project folder carries a CLAUDE.md (what the project is, where raw data lives, the rules), so a session never needs the context explained twice. Raw data is treated as read-only everywhere.

Coming from VS Code

Your Claude Code conversations in VS Code are kept on disk, per project folder, so closing the windows loses nothing but what was running at that moment. To continue one from the terminal: cc <name> -c resumes the latest conversation in that folder, or cd into it and claude --resume to pick from a list. Project context lives in each folder's CLAUDE.md, which every new session reads by itself. Use zsh, the Mac's default shell: cc doesn't exist in bash.

Install in three steps

1

Claude Code on the Mac

You need a Claude account (Pro or Max), the Claude desktop app, and Claude Code. The clearest walkthrough for non-developers is Chris Blattman's Install Claude Code (Mac); the short version:

curl -fsSL https://claude.ai/install.sh | bash
claude        # sign in once, then type anything to check it answers

Homebrew is needed for tmux and fzf: brew.sh, one command to paste.

2

The kit, in one paste

The script below contains every file of the kit (25 files, all plain text, nothing downloaded from anywhere). It writes them to ~/claude-kit and runs the installer: launcher, scripts, Quick Actions, tmux config, a scratch folder with a project template, and one line in your .zshrc. Read it first if you like; that is the point of shipping it as text.

  or download it (.zsh, 110 KB)

Then in Terminal: paste, press Enter. Or, to run it straight from the clipboard:

pbpaste | zsh
3

Lock it down, then first run

python3 ~/.config/claude-launcher/merge-settings.py   # sandbox + deny rules into ~/.claude/settings.json
cc ls                 # should show: scratch
cc new first-idea     # a project with its CLAUDE.md, Claude opens on it

The merge script backs up your settings, keeps every rule you already have, refuses a file that is already broken (and says which line), and validates the result. Don't paste the snippet by hand: a stray { ... } breaks the whole file.

In Apple Notes, create a folder named Claude (the kit reads nothing else), and in it a note titled to dos <today's date> with three lines: a meeting (“call X Thursday 3pm”), a reminder (“send the file to Y tomorrow”), a piece of work (“write a one-page summary of …”). Then cc inbox. macOS will ask once to let Terminal control Notes, Calendar and Reminders.

For each existing work folder: cd into it, cc add, then in the session ask Claude to write the project's CLAUDE.md. From then on cc <name> opens it with its context.

The daily loop

WhenWhat
AnytimeAdd lines to today's note: dictate (Siri: “note: …”), type, run cc todo "…", or ask a Claude session. Lines, not paragraphs: a verb, the input, the output.
Morning, Maccc inbox. Events and reminders land, tasks go to the cockpit rewritten as verb + input + output. cc me <id> on the ones only you can do, then cc run and walk away.
Back at the deskcc cockpit: tasks marked to review have their results in output/ with a README saying what to check. cc <session> then claude -c to keep working with the session that did it; cc clean to close the rest.
Through the daycc to jump into a session; Option+←/→ between them; Ctrl-b d to leave everything running.
When you sendCopy a draft from Reminders, send it yourself, tick it. The note and the cockpit follow within five minutes.
Weeklycc memo, dictate what the sessions can't know, cc memo --message, send.

Security

The rule: Claude drafts, you send. In this setup Claude has no connection to your email, WhatsApp or calendar, so it cannot send a message for you, and it cannot roam your whole computer.

Who does what

StepWhoWhat happens
1. CaptureYouYou add a line to your to-do note.
2. SortYour Maccc inbox classifies the line and puts it in the cockpit.
3. DraftClaude, in the sandboxA session works inside its project folder and writes a draft. It has no way to send it.
4. ReviewYouThe draft waits in Reminders. You read it and correct it.
5. SendYouYou paste it into your own mail or WhatsApp and press send. Claude is not involved.
6. CloseYou, then your MacYou tick the reminder. The note line gets its tick and the task leaves the cockpit.

What Claude can and cannot reach

AreaAccessHow that is enforced
Email, WhatsApp, MessagesNoneNo connector is installed, the Mail and Messages folders are blocked, and scripting other apps (osascript) is blocked.
CalendarNone unless you choose itLeave the calendar unset in config.json and no event is written.
Writing to diskProject folder onlyThe macOS sandbox refuses anything else, apart from the ledger, cockpit and queue.
Reading from diskMost of your home folder, except a blocked listSSH keys, keychains, cookies, mail, messages, .env files and keys are refused. Add your own sensitive folders to the list.
InternetA short list of sitesShell commands go through a filter. Anything not listed is refused.
Commit, push, deleteAsked firstPermission rules stop and ask. Queued sessions are told not to, and anything that needs asking is refused.

Keep the sandbox, add small exceptions

If the sandbox gets in your way, do not turn it off: queued sessions rely on it, and without it they would run with nothing around them. Exempt the few harmless commands you need instead, in ~/.claude/settings.json:

"sandbox": {
  "enabled": true,
  "autoAllowBashIfSandboxed": true,
  "excludedCommands": [
    "pbcopy",
    "pbpaste",
    "open *",
    "python3 ~/.config/claude-launcher/notes_ideas.py *"
  ]
}

That restores the clipboard, opening files and reading your to-do note. Do not exempt osascript: it can drive Mail, and that would undo the first row of the table above.

What this does not protect

  • Connectors you add. Connect your mailbox to Claude and this page no longer applies. Keep mail and WhatsApp out.
  • Your own approvals. You can allow a command outside the sandbox when asked. Read the prompt before you accept.
  • Reading. The sandbox limits writing much more than reading, so block what you would not want read.
  • Sensitive data. What a session reads is sent to Claude to be processed. Check your own rules before you point it at personal or research data.

The layers in detail

LayerRule
NotesOnly the Notes folder “Claude” is read; locked notes never; a line starting with 🔒, privé or // is skipped. The tick sync opens only notes whose title says “To dos”.
DiskClaude Code's sandbox (Seatbelt, enforced by macOS): sessions write only to their project folder plus the ledger, cockpit and queue; never read ~/.ssh, keychains, cookies, mail, messages, .env files or keys; never write to a raw/ folder. Cloud folders (~/Library/CloudStorage: Dropbox, iCloud Drive) can refuse sandboxed shell commands with “Operation not permitted”: test yours before you queue work that needs them.
NetworkShell commands reach only a short list of domains; web research goes through Claude's own tools, allowed for a list of reference sources you extend.
SecretsAPI keys in the macOS Keychain: security add-generic-password -a "$USER" -s <name> -T /usr/bin/security -U -w (the -T spares you a password prompt on every read).
AutonomyQueued sessions run in acceptEdits: file edits and sandboxed shell commands yes, anything else refused rather than asked. They never send, post, push or delete.

What it is not

It does not send anything. Messages and emails are drafts you copy and send yourself; sessions write files, never post. It does not touch raw data. It does not share anything across machines: the state lives in ~/scratch and ~/.config/claude-launcher on your Mac. And it is a set of plain zsh and Python files you can read in an afternoon, which is why it is shared this way rather than as an app.
